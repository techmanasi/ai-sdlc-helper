# Technical plan for code indexer setup in the web UI

Implement in the order below. Decisions Q1–Q8 govern the build declaration, API, action placement, and readiness rules. In particular, `buildArgv` declares process arguments and `build` supplies instructions for display. The inspection response includes `index` alongside `indexed`.

## Dependencies

- none

## 1. Resolve and inspect indexers in the engine

- In `src/config/codeSearch.ts:12`, add optional `buildArgv: string[]` to `CodeIndexer` and `buildArgv: 'string[]'` to `INDEXER_SCHEMA`. The existing `agent.codeIndexers` schema in `src/config/settings.ts:160` already consumes it. Give default Graft `['graft', 'build']` and keep default Graphify's manual instructions. In `codeIndexers`, retain the default argv for unrelated overrides such as moving the index path. When an override supplies a replacement `build`, use executable argv only if that override supplies its own `buildArgv`.
- In `codeSearchErrors`, validate declared argv as a nonempty array of strings with a `PROGRAM`-valid first element. Reject NUL in any element, which Node cannot pass to a process. Keep the PATH check at inspection and setup time so settings can describe tools that will be installed later. Keep existing display-only `build` declarations usable.
- Add `inspectCodeSearch(root, file, env)` to return `{ setting, current, indexers }`. Default the setting to `auto` and obtain `current` from `codeSearchFor`. For each resolved indexer return `{ name, command, index, installed, indexed, setup, build, canBuild }`. Use null for absent string fields. Reuse the existing `onPath` and project-relative existence checks. An absent index path reports `indexed: false`. Compute `canBuild` with a helper shared by inspection and execution that checks both the indexer's binary and the argv program on PATH. Keep the executable argv on the engine side.
- Export the inspection helper, its types, and the shared build lookup from `src/index.ts:6` for the web server's public package import. Keep `codeSearchFor`, `unavailable`, and `codeSearchGuide` semantics for the CLI, Doctor, and pipeline.

## 2. Add the project routes and execute builds

- In `web/server/index.ts:233`, dispatch exact GET `/api/projects/:project/code-search` and POST `/api/projects/:project/code-search/setup` paths after the existing project lookup and before context priming. These routes use the registered project root, the server's `env`, and the existing loopback, token, Origin, and JSON guards. Read `CONFIG_FILE` from the project root. Use an empty object for a missing file and surface parse or shape errors clearly. A stale selected indexer name can still be inspected and replaced.
- Validate the POST body as an object with a nonempty string `indexer` and optional boolean `build`, defaulting to false. Resolve the name as an own entry of `codeIndexers(file)`. Return HTTP 400 with `{ ok: false, error: "unknown indexer: '<indexer>'" }` for unknown names. For `build: true`, resolve the shared executable build lookup again on the server. Return HTTP 400 with `cannot build indexer '<indexer>': no executable build command or binary not on PATH` if that lookup fails. Validate the prospective config before launching a build using the same `fileErrors` validation as `editSettings` on an `applyPatch` result. Export `fileErrors` through `src/index.ts` for this check.
- Add a subprocess helper in `web/server/index.ts` alongside `runCommand` at line 208. Use Node's existing `spawn` with the resolved program and literal argv, `shell: false`, `cwd: p.path`, the server environment, ignored stdin, and piped stdout and stderr. Follow the existing output capture limits, retain both streams in the response, and handle spawn errors, signals, and nonzero exit codes. Use `COMMAND_TIMEOUT_MS` (120 seconds), terminate a timed-out child, and clear the timer on settlement. Ensure a child that ignores graceful termination or leaves its output pipes open cannot hold the HTTP response indefinitely. Keep the command palette's CLI invocation and timeout behavior intact.
- Track an in-flight build by project root to prevent overlapping setup operations for the same project, releasing the guard in `finally`. Return HTTP 400 with the build error and any captured output on failure, including `build timed out after 120s` on timeout. Only after a successful build or a configure-only request, call `editSettings(p.path, { agent: { codeSearch: indexer } }, hash)`. Use the hash of the config snapshot examined before execution so that a concurrent settings save is surfaced as an edit error. This uses the existing atomic write, preserves sibling settings, and creates a missing file. Configure-only requests may select any known indexer, as specified by the API contract.
- On a successful save call `dropContext(p.name)`, run `doctor(p.path, { env })`, and return HTTP 200 with `{ ok: true, codeSearch: indexer, checks, output? }`. Include `output` for a build and omit it on configure-only success. Return an `editSettings` validation or hash conflict as HTTP 400 with the same error shape and any build output already collected.

## 3. Add the browser API and setup dialog

- In `web/ui/src/api.ts:137`, mirror the inspection, request, and result types following the browser's existing practice for API contracts. Add `api.codeSearch(project)` and `api.setupCodeSearch(project, body)` using the encoded project path from `p(project)` and the existing `call` helper. Extend `ApiError` and `failure` at lines 151–158 to preserve optional string `output` from failed requests while retaining the existing error message fallbacks.
- Create `web/ui/src/CodeSearchModal.tsx` with the project, open state, close handler, and `onConfigured(result)` callback. Fetch fresh inspection on open. Ignore stale inspections after project changes or a newer request. Use the `Projects` dialog markup at `web/ui/src/Projects.tsx:380` and reuse `dialogKey`, `focusable`, and `firstFocusable` from `web/ui/src/dialog.ts`. Share the DOM-to-focus-candidate logic from `Projects.tsx:305`. Give the overlay `role="dialog"`, `aria-modal="true"`, `aria-label="Code Search Setup"`, and `tabIndex={-1}`. Focus the first available control or the overlay, trap Tab and Shift+Tab, support Escape and backdrop dismissal, and restore focus to the trigger if it still exists or to a stable nearby control. Title the dialog `Code Search Setup · <project>`.
- Show configured and effective settings, a current badge for the explicitly selected indexer, installation status, and index status with the inspected path when present. Use the following actions.

  | Indexer state | Actions |
  | --- | --- |
  | Binary missing | Disable setup actions. Show installation instructions and use `CopyButton` when instructions are available. For default Graft and Graphify, copy the install command and show the rest of the instructions separately. |
  | Installed and indexed | `Use <indexer>` sends `build: false`. Show `Rebuild Index` with `build: true` when `canBuild`. |
  | Installed with no index path | Show `No index required` and use the same actions as for an indexed tool. |
  | Installed, unindexed, executable build | `Build Index` sends `build: true`. |
  | Installed, unindexed, manual build | Disable `Build Index` and show copyable instructions. For default Graphify, display the Claude Code context and copy the `/graphify .` invocation. Show `Configure (agent.codeSearch: <name>)` disabled and offer `Refresh status`. If the index appears during that dialog session, enable `Configure` and send `build: false`. An index already present when the dialog opens takes the `Use <indexer>` path. |

- During a setup request disable action and copy buttons, show an announced loading state, and keep focus within the overlay while open. Keep the request pending across dismissal so reopening cannot submit it twice and the owning view still receives a successful result. Render failures with `ErrorBox` and captured output in a scrollable `pre.code.mono`. On success show a toast, call `onConfigured(result)`, and close the dialog.
